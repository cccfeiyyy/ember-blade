## 1. 概览（Overview）

回响祝福是 v2 的单局构筑系统：每局开局与每波清场后，系统从候选池中抽取 3 条祝福供玩家选择其一。祝福分普通 / 稀有 / 史诗三档，可叠加（各有叠加上限），全部效果通过 `P.mods` 统一聚合，战斗系统只读取聚合后的修正值。

设计意图：把「打得漂亮」转化为「构筑更强」，并用 22 条小而清晰的条目（而非海量随机词条）保证单局内能形成可辨认的流派，同时控制实现与平衡成本。

---

## 2. 玩家幻想（Player Fantasy）

> 「竞技场记得每一次挥剑。你选择让哪一段回响留在刃上。」

玩家应感到：每次三选一都在回答一个问题——「我是靠连击压制、靠弹反反击、靠处决回血，还是靠灼烧磨死它？」同一条祝福叠到第二、三层时，玩法会发生可见的质变（如「完美余音」让弹反后的三秒变成爆发窗口）。

---

## 3. 详细设计

### 3.1 核心规则

| 规则 | 内容 |
| --- | --- |
| 获取时机 | 开局（第 1 波前）1 次；每波清场后 1 次（主流程共 5 次；无尽每波 1 次，无 Boss 波双选） |
| 选择形式 | 三选一，鼠标点击或数字键 `1/2/3`；重复条目不出现在同一组候选中 |
| 稀有度 | 普通（common）/ 稀有（rare）/ 史诗（epic），基础权重 62 / 28 / 10，随波次漂移（见 §4.2） |
| 叠加上限 | 每条祝福有独立 `max`（普通多为 3、稀有多为 2、部分功能型为 1、史诗均为 1） |
| 生效方式 | 选取后 push 进 `P.blessings`，调用 `G.recalcBlessingMods(P)` 全量重算 `P.mods` 与派生上限 |
| 不可撤销 | 选择即生效，本局不可重置（除死亡/重开） |
| 暂停语义 | 选择期间游戏世界暂停（`S.mode = 'blessing'` 或等价暂停态），不推进计时、不结算波次 |
| 初始池 | 第 1 波前的一选同样走权重抽取，但波次参数按 `wave = 0` 计算 |

### 3.2 状态与转换

```
[wave clear] --(清场奖励结算完毕)--> [blessing: offer] --(选择/键盘)--> [blessing: apply]
      ^                                                                        |
      |                                                                        v
[playing: next wave] <--(recalc mods / HUD 更新 / 音效)------------------ [blessing: close]
```

- 进入条件：`S.mode === 'playing'` 且 `waveState === 'clear'`，或开局 `startGame()` 之后、第一波开始之前。
- 退出条件：必须选择 1 条（不可跳过；候选池为空时自动跳过并给出「回响已尽」提示）。
- 边界：Boss 死亡进入胜利结算时不再发祝福；无尽模式 Boss 波清场发 2 次，按顺序弹两次三选一。

### 3.3 与其他系统的交互

| 系统 | 交互 |
| --- | --- |
| SYS-03 玩家动作 | 读取 `P.mods` 的伤害/速度/体力/药水/处决阈值等；祝福不得直接改动作帧 |
| SYS-08 风格评价 | `perfectBuff`（完美余音）由风格/弹反事件触发增伤计时；`keepCombo`（无限连）读取受击清连击逻辑 |
| SYS-09 掉落 | `lifesteal`（噬魂）与掉落治疗并存，注意叠加上限与来源区分 |
| SYS-05 波次/无尽 | 波次号作为稀有度漂移参数；每波清场触发一次选择（无尽同样 1 次） |
| SYS-10 HUD | 左上角祝福图标列表（`#blessing-list`）、三选一界面（`#blessing-screen`）、已叠加层数徽标 |
| SYS-11 音频 | `blessingOpen`（界面打开）、`blessingPick`（按稀有度变体） |
| SYS-12 持久化 | 祝福**不**落盘，仅单局内存状态 |

### 4.2 稀有度权重（`rarityWeight(rarity, wave)`）

| 稀有度 | 基础权重 | 波次漂移公式 | 边界 |
| --- | --- | --- | --- |
| 普通 | 62 | `max(18, 62 - wave × 2)` | 后期越来越低 |
| 稀有 | 28 | `min(52, 28 + wave × 2.5)` | 后期上升 |
| 史诗 | 10 | `min(40, 10 + wave × 3.5)` | 后期上升 |

- 抽取流程：候选池 = 未达 `max` 的祝福；先按「该稀有度权重之和」掷骰决定稀有度，再在该稀有度内等概率取一条；不重复取同一条，最多取 3 条（`guard` 上限 200 次）。
- 主流程（第 1–5 波）实际波次参数：开局 `wave=0`、清第 1 波后 `wave=1` … 清第 4 波后 `wave=4`；Boss 波无祝福。

### 4.3 重算规则（`G.recalcBlessingMods(P)`）

```
P.mods = blessingModsBase()
for b in P.blessings: b.apply(P); counts[b.id]++
P.maxHp       = max(50, 100 + P.mods.maxHpBonus)
P.maxStamina  = 100 + P.mods.staminaMaxBonus
P.maxPotions  = 3 + P.mods.potionMax
clamp(P.hp ≤ P.maxHp, P.stamina ≤ P.maxStamina, P.potions ≤ P.maxPotions)
```

- 乘法祝福直接乘在 `mods` 字段上（例如锋锐 ×1.15、重势 ×1.2），叠 3 层即 `×1.15³ ≈ ×1.52`。
- 负向词条（双刃 −20 生命上限）也走同一 `maxHpBonus`，受 `max(50, …)` 兜底下限保护。
- 重算必须幂等：重复调用不得累加（先重置再 apply）。

### 4.4 期望节奏

| 节点 | 累计选择次数 | 说明 |
| --- | --- | --- |
| 开局 | 1 | 通常 1 普通/稀有，确定本局初始倾向 |
| 清第 1 波 | 2 | 开始形成 1 条 2 层或 2 条 1 层 |
| 清第 2 波 | 3 | 稀有概率上升，通常出现第一张稀有 |
| 清第 3 波 | 4 | 冲刺期，史诗进入候选概率约 20%+ |
| 清第 4 波 | 5 | Boss 前最后一选，决定 Boss 战策略 |
| 无尽模式 | +1/波，Boss 波 +2 | 约第 10 波时史诗候选概率显著 |

## 6. 边界情况（Edge Cases）

| 场景 | 期望行为 |
| --- | --- |
| 候选池不足 3 条（全部满层） | 返回可抽到的数量；若为 0 则直接跳过选择并提示「回响已尽」，不阻塞波次 |
| 同类祝福达上限 | 从候选池剔除；已叠加层数仍生效 |
| 选择时敌人尚未完全消失（消散动画） | 世界暂停，动画冻结；恢复后继续 |
| 玩家在清波瞬间死亡 | 优先进入死亡流程，取消本次祝福；不允许「死后选祝福」 |
| 双刃使生命上限低于当前生命 | `hp` 被 clamp 到新上限，不返还溢出生命 |
| 不屈/饮者选取瞬间 | `onPick` 立即回复/补药，随后 `recalc` 再 clamp；顺序不得颠倒 |
| 重复调用 `recalc` | 幂等，不允许数值翻倍 |
| 未知祝福 id | `getBlessing()` 返回 undefined；读取方需跳过，不得崩溃 |
| 快捷键 1/2/3 | 仅在祝福界面激活时生效；不穿透到暂停/标题页 |
| 无尽模式连续两次选择 | 第二次选择界面在第一次关闭后弹出，不得叠层显示 |

## 8. 可调参数（Tuning Knobs）

| 参数 | 位置 | 当前值 | 调整影响 |
| --- | --- | --- | --- |
| 稀有度基础权重 | `blessings.js` `RARITY` | 62 / 28 / 10 | 提高稀有会加快构筑成型 |

## 9. 视觉 / 音频要求

- 祝福图标为单字（锋/重/疾/…），由 HUD 渲染在左上角 `#blessing-list`，同名叠加显示层数（如「锋 ×2」）。
- 三选一卡片：稀有度边框与光效（普通灰白、稀有青蓝、史诗紫焰），卡片含数字键、稀有度标签、单字图标、名称、效果文案、风味文案（当前实现不显示已持有层数，层数见 HUD chip）。
- 音频：界面打开播放 `blessingOpen`（空灵上行和声）；选择确认播放 `blessingPick`，稀有度越高和弦越华丽（实现按 `opt.rarity` 分档：普通三和弦、稀有加高音、史诗三角波+高次泛音）。

## 11. 验收标准

- [ ] AC-1：开局进入祝福三选一，选择后第 1 波开始，`P.blessings.length === 1`。
- [ ] AC-2：每波清场后弹出三选一；主流程共 5 次波后选择（清 1–4 波各 1 次 + 开局 1 次 = 5 次）。
- [ ] AC-3：22 条祝福均可抽取；达到 `max` 后不再出现。
- [ ] AC-4：同一祝福叠 2 层后效果按乘法叠加（如锋锐 ×1.15² ≈ ×1.3225）。
- [ ] AC-5：选择后 `P.mods` 与派生上限（`maxHp/maxStamina/maxPotions`）同步更新，且 `recalc` 幂等。
- [ ] AC-6：稀有度权重随波次漂移，后期稀有/史诗出现率上升（统计 100 次抽取验证趋势）。
- [ ] AC-7：选择界面期间游戏暂停；选择后恢复；死亡/胜利流程不弹祝福。
- [ ] AC-8：选择界面支持鼠标与 1/2/3 键；不穿透到其他界面。
- [ ] AC-9：进入无尽模式后祝福继续按规则发放（每波 1 次，无 Boss 波双选）。

## 12. 开放问题

1. 是否需要在祝福界面显示当前整体构筑（已有条目列表）以辅助决策？当前仅左上角 HUD 图标，空间有限；实现上卡片未显示「已持有层数」。
2. `auraHeal` 字段已预留但无祝福使用——是否在 v2.1 加入「靠近敌人持续回血」类祝福？
3. 史诗 6 条中 `dualBlade` 的 −20 生命上限是否会被 `max(50,…)` 兜底意外抵消（生命上限 100→80，不会触底）；多诅咒叠加时需复核。
4. 祝福选择是否应允许「跳过并换取少量势能」？当前不允许，避免负向体验与数值漏洞。
