## 1. HUD 哲学（HUD Philosophy）

**「最小但完整 —— 战斗中每个数字都必须能一眼读完，且只出现在需要它的位置。」**（Minimal but present，偏信息密集动作游戏）

三条约束：
1. **中心留给战斗**：屏幕中央只允许出现敌人预警、伤害数字、处决提示与短暂大字，不布置常驻信息。
2. **资源在边缘**：生命/体力/药剂在左下、势能/技能在右下、得分/计时/祝福在左上、连击/风格在右上、波次在正上——与玩家视线焦点（准星/Boss）保持距离。
3. **状态变化必须可感知**：低血、势满、风格升级、弹反成功、破绽出现，全部要同时有「视觉 + 音频/触觉（屏幕震动）」双通道反馈，不能只改数字。

### 2.2 分类原则与冲突检查

- Must Show 共 12 项，其中属于「实时数值」的仅 6 项（生命/体力/势能/技能/得分/连击），符合动作游戏「先看战斗、后看数字」的注意力模型。
- 祝福界面强制暂停世界，因此不需要在战斗中展示「选择倒计时」。
- 敌人血条/精英标识/破绽提示均为世界空间，不占用 HUD 边缘区。
- 明确 Hidden（不显示）：精确伤害公式、祝福抽取概率、隐藏的势能衰减速率、内心独白式叙事文本。

## 3. 布局分区（Layout Zones）

### 3.1 布局原则

- 16:9 桌面基准，四角信息区距屏幕边缘 28–36px；中心 50% 区域只放战斗反馈。
- 左下资源区与右下技能区形成「生存/进攻」对角线，符合双手操作（WASD 左手、鼠标右手）的余光可及范围。
- 右上风格盒与左上得分/祝福形成「表现/记录」呼应；风格盒在战斗中更重要，因此放在鼠标手侧。

## 5. 回响祝福界面（Blessing Screen）

### 5.1 目的与入口

- **目的**：让玩家在 3 张卡之间做出有信息的构筑选择，同时保持竞技场仪式感与「回响」主题。
- **入口**：开局（第一波前）、每波清场后（主流程第 1–4 波后）、无尽模式每波清场后（Boss 波连续两次）。
- **出口**：选择后 430ms 播放卡片确认动画并关闭，恢复指针锁定，进入下一波。
- **暂停语义**：世界完全暂停；HUD 仍可见（可看到当前构筑与资源）；`Esc` 在祝福界面无效（必须选择）。

### 5.2 布局与组件

```
┌──────────────────────────────────────────────────────────────┐
│                    ECHOES OF THE BLADE                        │
│                       选 择 回 响                             │
│                 初始回响 · 选择你的第一道力量                  │
│                                                              │
│   ┌────────────┐    ┌────────────┐    ┌────────────┐         │
│   │ [普通]      │    │ [稀有]     │    │ [史诗]      │         │
│   │   锋        │    │   时之砂    │    │   回响之主   │         │
│   │  锋锐       │    │  ...       │    │  ...        │         │
│   │ 轻斩伤害+15%│    │            │    │             │         │
│   │ 已持有 ×1/3 │    │ 已持有 ×0/1 │    │ 已持有 ×0/1 │         │
│   │ 剑锋所至…   │    │ 你听见时间… │    │ 竞技场记得… │         │
│   │   [选择]    │    │   [选择]    │    │   [选择]    │         │
│   └────────────┘    └────────────┘    └────────────┘         │
│                 点击卡牌 或 按 1 / 2 / 3 选择                  │
└──────────────────────────────────────────────────────────────┘
```

组件清单（源码事实 `template.html` / `hud.js` / `style.css`）：
- `#blessing-screen`（覆盖层，z-index 44，径向渐变暗化背景）
- `.blessing-panel`（容器，含 kicker「ECHOES OF THE BLADE」、标题「选 择 回 响」、说明 `#blessing-note`、卡片区 `#blessing-cards`、底部提示「点击卡牌 或 按 1 / 2 / 3 选择」）
- `.blessing-card`（3 张，稀有度类：`.common/.rare/.epic`），卡面结构：
  - `.card-key`：左上数字键（1/2/3，等宽字体）
  - `.card-rarity`：稀有度文字标签（普通/稀有/史诗，按稀有度着色）
  - `.card-icon`：单字图标（锋/重/疾/…）
  - `.card-name`：祝福名称（宋体）
  - `.card-desc`：效果文案
  - `.card-flavor`：「风味文案」（灰色斜体/引号）
- 卡片交互：悬停上浮 8px + 缩放 1.015 + 稀有度光晕 + `uiHover` 音效；整张卡可点击；数字键 1/2/3 选择；选中后加 `.picked`（放大 + 其余淡出 0.25），`cardPick` 动画 0.38s；`game.js` 记录 `blessingPicked` 并在 **0.45s** 后调用 `finishBlessing()` 关闭界面、恢复指针锁定并进入下一波（选择期间重复点击/按键被忽略）。
- 实现差异：卡片**不显示**「已持有层数」；已有层数只在左上 HUD 祝福 chip 的右下角以数字显示（见开放问题）。

### 5.3 状态与变体

| 状态 | 表现 |
| --- | --- |
| 默认 | 三卡等宽居中（250×310px），暗色背景径向渐变；卡片依次入场（延迟 0/0.08/0.16s） |
| 悬停 | 卡片上浮 8px + 缩放 1.015、稀有度边框增强 + 光晕、`uiHover` 音效 |
| 选择中 | 选中卡加 `.picked`（放大 + `cardPick` 动画），其余卡透明度 0.25 |
| 候选不足 3 张 | 只显示可抽数量；若为 0 则不弹界面（直接进入下一波） |
| 无尽模式 | 每波清场后 1 次（含 Boss 波；当前实现无 Boss 波双选） |
| 达上限祝福 | 不进入候选，因此不会出现禁用卡 |

### 5.4 数据需求

- `G.rollBlessingChoices(P, wave, 3)` 返回候选数组，每项含 `id/name/icon/rarity/desc/flavor/max`。
- 当前层数来自 `P.blessingCounts[id]`。
- 稀有度标签与颜色来自 `G.BLESSING_RARITY`。

## 6. 标题页、暂停/设置、结算页与无尽

### 6.1 标题页（`#title-screen`）

- 保留 v1 电影感标题、副标题、开始按钮。
- 最高纪录块 `#best-record`（源码事实）：
  - 无纪录：「尚无纪录 · 成为第一个回响」
  - 有纪录：「最高纪录 · 得分 X · 无尽 第 N 波 · 通关 N 次」（按已有字段拼接）
- **操作说明（已实现）**：标题页控制区已补 `Q 格挡 · 精准弹反` 与 `1 / 2 / 3 选择回响`，共 12 项。
- 进入标题页时音乐 `title`；点击开始后音乐 `battle`。

### 6.2 暂停/设置页（`#pause-screen`）

| 控件 | 类型 | 范围/选项 | 行为 |
| --- | --- | --- | --- |
| 鼠标灵敏度 `#sens-slider` | 滑条 | 0.3–2.0，步长 0.1 | 实时生效，`saveSettings()` 持久化 |
| 音量 `#vol-slider` | 滑条 | 0–100 | 实时生效并持久化 |
| 反转纵向视角 `#invert-y` | 复选框 | 开/关 | 仅反转鼠标 pitch 输入，不影响锁定回正 |
| 画质 `#quality-select` | 下拉 | 自动/高/低 | 即时应用（`applyQualityMode()`）并持久化 |
| 继续/重新开始/返回标题 | 按钮 | — | 既有行为 |

- 设置存储键：`emberblade_settings_v2`（`{sens, volume, invertY, quality}`，实现事实）。
- 暂停时世界冻结、HUD 保留。

### 6.3 结算页（`#end-screen`）

- 标题与 kicker（源码事实 `hud.showEnd`）：
  - 主流程胜利：kicker `THE CYCLE ENDS` / 标题「逃 出 生 天」；评级按 `得分 + 时间奖励 + 生命奖励 + 药剂奖励` 计算（S≥38,000 / A≥29,000 / B≥21,000 / C）。
  - 主流程失败：kicker `THE CYCLE CONTINUES` / 标题「余 烬 熄 灭」；评级按到达波次（≥5 波 A / ≥4 波 B / ≥3 波 C / 否则 D）。
  - 无尽结束：kicker `THE ECHO ENDURES` / 标题「回 响 止 步」；评级按到达波次（≥15 波 S / ≥10 波 A / ≥7 波 B / 否则 C），note 显示「无尽回响 · 止步于第 N 波 · 评级 X」。
- 评级徽章 `#end-rank`：D/C/B/A/S，颜色分级（S 金色光晕、C/B/A 递增、D 降饱和）。
- 统计网格：得分、用时、击破、最高连击。
- `#end-record`（源码事实）：显示「历史最高得分 b」+（若有）「无尽最高 第 N 波」+ 新纪录时「◆ 新纪录」。
- 按钮：再战一次（`#again-btn`）；**无尽回响**（`#endless-btn`，仅在 `victory && !endless` 时显示）；返回标题（`#end-quit-btn`）。
- 实现注意：无尽结束时不显示「无尽回响」按钮（`hud.showEnd` 条件），而 `game.startEndless()` 本身允许从死亡态进入——当前 UI 不提供再次无尽入口，记入开放问题。

| 小窗口/低分辨率 | 采用相对布局与 clamp 字号；1280×720 仍可读 |
| 帧率波动 | 逻辑使用限幅时间步（≤0.05s）；弹反窗口按时间而非帧计数 |

## 11. 验收标准

- [ ] AC-1：战斗 HUD 在 1280×720 与 1920×1080 下四角信息不重叠、不遮挡中心战斗区。
- [ ] AC-2：生命/体力/势能/连击/风格/波次/得分实时更新且数值与 `__DEBUG.state()` 一致。
- [ ] AC-3：局部元素按 §4 规格展示，技能行包含 Q/SPACE/E 三项。
- [ ] AC-4：祝福界面可用鼠标与 1/2/3 键选择；选择后 430ms 内完成动画并恢复战斗；`Esc` 无效。
- [ ] AC-5：祝福卡片显示稀有度、效果、风味；稀有度样式可区分；已叠层数在左上 HUD chip 显示（卡片内不显示，见开放问题）。

## 12. 开放问题

1. ~~**标题页操作说明缺 Q**~~ → **已解决**：`template.html` 已补 `Q 格挡 · 精准弹反` 与 `1/2/3 选择回响`。
2. **祝福卡片不显示已持有层数**：当前实现仅在 HUD chip 右下角显示层数；若后续空间允许，建议在卡片上增加「已持有 ×N / M」以辅助「是否叠层」决策。
