## 1. 目标与范围

### 1.1 测试目标

1. 在**真实浏览器环境**（非 mock）中验证 v2.0 全部新增功能可用、可交互、可结算。
2. 验证 v1.0.1 既有玩法**无回归**（连击、闪避、剑气、烬灭、锁定、波次、Boss、结算、暂停）。
3. 验证**持久化**（设置、无尽最高纪录）跨刷新有效，且损坏数据不导致崩溃。
4. 验证**全程控制台零报错**（含未捕获异常、Promise rejection、`window.__ERRORS`）。
5. 产出可复核的证据（截图 + 结构化结果 JSON）与可发布结论（PASS / FAIL / 带条件 PASS）。

### 1.2 范围（In Scope）

| 模块 | 优先级 | 说明 |
| --- | --- | --- |

### 1.3 不在范围（Out of Scope）

- 移动端/触屏适配、Firefox/Safari/Edge 兼容性（目标平台为桌面 Chrome）。
- 音频听感的主观音质评价（无头环境静音；只验证 WebAudio 状态、音量/静音开关与音乐模式切换的**逻辑**，听感由人工试玩补充）。
- 构建流程正确性（由 Lead 负责；QA 只对构建产物做「新鲜度/完整性」校验）。
- 数值平衡的深度调参（由 design-docs / Lead 负责；QA 只记录异常体验并写入 playtest）。
- 修改游戏代码、源码、构建脚本、README、设计文档。

## 3. 准入 / 准出标准

### 3.1 准入（Entry Criteria）——不满足即 BLOCKED 并立即上报 Lead

- [ ] 收到 Lead 的 `V2_BUILD_READY`，含构建时间/版本信息。
- [ ] `index.html` 存在、mtime 不早于 `.dev/src` 最后修改时间、大小在合理区间（约 0.8–2 MB）。
- [ ] 页面加载后 `window.__READY === true` 且 `window.__DEBUG` 存在。
- [ ] `window.__DEBUG.version` 为 2.x（若仍为 1.x → 构建未生效，立即上报）。
- [ ] 标题页可见、无错误页（`#error-screen` 不可见）、加载后控制台零 error/exception。
- [ ] 能力探针（`00-probe`）记录的新增控件/调试钩子清单已核对。

### 3.2 准出（Exit Criteria）

- [ ] 全部 **P0** 用例 PASS；P1 用例无「阻断/严重」级失败（允许记录为已知问题并给出 workaround）。
- [ ] 无 S1（阻断）与 S2（严重）缺陷未关闭；S3/S4 已登记 `production/qa/bugs/`。
- [ ] 全流程控制台零未预期 error/exception，`window.__ERRORS.length === 0`。
- [ ] 证据截图覆盖每个 P0 模块（见 §8 截图清单）；截图含构建标识（文件名 tag）。
- [ ] 持久化用例（设置 + 无尽纪录）跨刷新 PASS。
- [ ] 性能粗测有数据记录（战斗 ≥ 60s、Boss 二阶段）；无持续恶化/崩溃。
- [ ] `production/qa/qa-report-v2.md` 完成，结论明确（PASS / 带条件 PASS / FAIL）。
- [ ] `production/playtests/playtest-v2.md` 完成（可玩性观察、主观问题、建议）。
- [ ] Lead 收到 QA 结论消息。

### 3.3 中止/例外判定

- 任一 S1 阻断（无法进入游戏、必现崩溃、主流程卡死、二阶段无法触发等）→ 立即 `send_message` lead，可先交「部分验收」报告。
- 构建在测试期间被覆盖（运行前后 SHA-256 不一致）→ 本次结果作废，重新运行。

## 4. 风险与缓解

| # | 风险 | 影响 | 缓解措施 |
| --- | --- | --- | --- |
| R1 | 测试期间 Lead 仍在改代码/重新构建，产物变动 | 结果不可信 | 运行前后记录 `index.html` SHA-256 并比对；变化则重跑 |
| R2 | v2 `__DEBUG` 接口与计划预期不一致 | 自动化阻塞 | 探针先跑，记录能力表；用例优先使用**行为/UI 级**断言，白盒仅作辅助；缺失钩子标记 BLOCKED 而非 FAIL，并改用输入模拟 |
| R3 | 无头环境 Pointer Lock/音频被策略限制 | 误判 | 状态类检查白盒辅助；声音验证降级为逻辑验证并在报告注明限制 |
| R4 | 弹反/处决/Boss 攻击等强时序机制难以稳定复现 | 随机失败 | 使用 `tick()` 确定性推进 + 状态轮询；Boss 攻击按「观察窗口内至少出现一次」判定，多次重试；记录状态直方图作为证据 |
| R5 | 软件渲染帧率低、截图慢 | 性能误判 | 性能只作粗测；阈值放宽并注明环境；逻辑测试主要用 tick |
| R6 | localStorage 残留或脏数据 | 持久化用例假阳性 | 每轮独立临时 profile；必要时主动清空；额外做「损坏 JSON 容错」用例 |
| R7 | 祝福/处决等新 UI 的 DOM id 未知 | 脚本选择器失效 | 探针输出可见覆盖层/按钮快照；采用「文本/可见性/层级」启发式选择器；选择失败时导出 DOM 供报告 |
| R8 | 单会话长时间运行内存/上下文膨胀 | 后续用例抖动 | 每个套件间按需 `Page.reload`；必要时分段运行；记录异常 |

## 5. 缺陷分级与处置

| 级别 | 定义 | 示例 | 处置 |
| --- | --- | --- | --- |
| S1 阻断 | 无法开始/继续游戏，主流程不可达，必现崩溃 | 标题按钮无响应、Boss 二阶段永不触发、启动报错 | 立即上报 Lead，验收判 FAIL |
| S2 严重 | v2 核心功能失效或严重错误 | 弹反无法触发/无尽纪录不保存/设置不生效、刷怪后卡死 | 上报 Lead，验收「带条件 PASS」需 Lead 确认 |
| S3 一般 | 功能可用但有明显缺陷 | 个别祝福图标缺失、伤害数值异常、HUD 显示错误 | 登记 bug-NNN，允许发布前排期 |
| S4 轻微 | 体验/文案/视觉小问题 | 文案错别字、音效音量偏小、动画轻微穿插 | 登记 bug-NNN 或写入 playtest 建议 |

Bug 报告模板（`production/qa/bugs/bug-NNN.md`）：标题 / 严重级 / 构建标识 / 环境 / 前置条件 / 最小复现步骤 / 期望 / 实际 / 证据（截图路径）/ 复现率 / 备注。

> 所有用例默认从标题页或新开局开始，前置数据见「前置」列。期望值中的具体数值以 v2 构建与 GDD 为准，若 GDD 未给数值则验证**相对行为**（提升/降低/不生效）。

## 9. 执行策略与调度

1. **构建核验**（< 1 min）：记录 `index.html` mtime/size/SHA-256；启动探针，确认 `__DEBUG.version` 为 2.x、能力表与 DOM 快照。
2. **P0 主流程串行**（约 8–12 min）：标题 → 祝福 → 战斗/弹反/风格/处决 → Boss 二阶段 → 无尽/持久化 → 暂停设置 → 死/胜利 → 控制台。
3. **P1/P2 补测**（约 5–8 min）：精英、爆裂者、掉落、性能、回归、边界。
4. **失败隔离**：任一用例失败不中止套件；套件失败不中止全量；收集完整证据后统一判定。
5. **复跑策略**：时序类失败（弹反/Boss 攻击）默认自动复跑 1 次再定级；构建变动必须整体复跑。
6. **人工试玩**（10–15 min）：1 局完整流程（含祝福构筑选择）+ 1 局无尽，记录可玩性/难度/节奏/反馈，写入 playtest 报告。

## 11. 已知限制

1. 无头 Chrome + SwiftShader 的性能不代表真机；FPS 仅作粗测，不作为硬性性能结论。
2. 音频听感不可自动化评价；只验证逻辑与状态。
3. Pointer Lock 在无头环境可能不可用；视角/反转Y验证使用调试注入 + 相机状态白盒读取，属于「逻辑可用」而非「真实鼠标链路」证据，需人工试玩复核。
4. 时序类机制（精准弹反、Boss 攻击随机序列）的覆盖依赖轮询与重试，存在少量不稳定；报告中会标注 `FLAKY` 与重试次数。
5. 若 v2 构建未暴露某功能对应的调试钩子，相关用例自动降级为 UI/行为级验证或标记 BLOCKED（附诊断信息），不伪造 PASS。
